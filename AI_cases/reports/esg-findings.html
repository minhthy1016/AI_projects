No sustainability report had to be sourced separately. Under CSRD the sustainability statement sits inside the annual report — OMV pages 29–80, Aker BP pages 33–140 of the same file already downloaded for the financial extraction.

Why these documents make a good test

The rendered PDF strips every XBRL tag and leaves only visual layout — the hard input. The .json shipped alongside keeps the tagged values — the label. One document therefore yields a matched pair of hard input and exact ground truth, at zero annotation cost. On the financial side this now runs across all eight ESEF filers in the corpus — six languages — at 100% exact match on every one: of 238 extracted values, 223 are comparable against the filing's own XBRL and all 223 are exact. The other 15 the filer never tagged, so they count in neither numerator nor denominator. Recall within each filer's declared label map ranges 82.9% (Eni) to 100% (TotalEnergies), the shortfall being almost entirely comparative-year columns absent from two-column tables.

The financial layer scaled; this one did not

That asymmetry is not a matter of effort. Each ESEF filing ships its own XBRL, so the financial extraction gets an exact, free label for every figure — which is why eight filers cost little more than two. Sustainability statements ship no equivalent. Every ESG figure below was checked by opening the cited page by hand, so extending this section costs real annotation time. 113 of the project's 351 extracted rows carry no ground truth at all, and all of them are on this side of the line.

What the extraction is measured against

Two numbers govern every claim on this page. Exactness: of the values pulled out, how many match the filing's own XBRL to the digit. Recall: of the values the filer's label map declares, how many were actually reached. They answer different questions, and reporting only the first is how a system that reads one row correctly scores 100%.

Green bar is recall within each filer's declared label map; the figure on the right is exactness. Eight filers, six languages, 223 of 223 comparable values exact. Recall shortfalls are almost entirely comparative-year columns that the printed table does not carry.

A ceiling with no floor is not a readable number

Before trusting any of it: when a value is not found, is that because the reader missed it, or because it was never in the document? The standard answer is a ceiling — count how many gold values appear in the parsed text at all, before any extractor runs. But that count matches by value across the whole bag of numbers, position-free, so it needs a floor: score the same gold against a different company's filing and see what coincidence alone buys.

Measured on the full ~300-page filing the ceiling reads 99% — but the floor is 87%, so almost all of it is coincidence. Narrowing to the statement pages the extractor actually sees leaves the ceiling at 98% and drops the floor to 11%. Same ceiling, an 86-point real gap instead of 12. The two ceiling points that differ turned out to be false matches: gold records income-tax expense as +1834 per taxonomy sign convention while the document prints –1.834, and somewhere in 300 pages a different +1834 exists.

Not a machine-learning result

Greenwashing has no ground truth, so nothing here is a classifier output. These are inconsistency signals computed by rule from normalised disclosures, each carrying a page number, a table id, a column header path and the verbatim string. Every figure below can be checked by opening the cited page. Two company-years is a pilot, not a dataset.

Internal consistency

The target block (E1-4, page 64) declares a baseline of 13.9 Mt CO2e. The emissions table (E1-6, page 67) gives 13,920,157 t = 13.920 Mt for the same year. Two separate places in the document, same number — the disclosure reconciles with itself.

That check is not decorative. It is what caught a silent one-column offset in the first extraction run, where the 2019 baseline value had been assigned to 2024. Every figure stayed plausible; only the cross-reference revealed it.

ESRS content index reconciliation

The index on pages 124–125 claims 70 disclosure requirements are reported, each with a page reference. Reconciling every claim against where the disclosure actually appears — bracketed ESRS tags or section headings — gives 70 of 70 verified, plus 8 incorporation-by-reference rows whose target notes all resolve.

A clean result is a useful result

A negative finding calibrates the detector. It shows the check does not manufacture signal where none exists, which is what makes it credible when it does fire on another filer. A signal is only usable once you know its false-positive rate; on this document, after fixing six defects of my own, that rate is zero.

The basis question

Scope 1 (838) plus location-based Scope 2 (14) equals 852, which matches the reported total of 853 within rounding at kilotonne precision. Scope 1 plus market-based Scope 2 (575) equals 1,413, which does not. The headline total is therefore built on location-based Scope 2 — the smaller of the two figures the company publishes, by a factor of 41.

Measured on that basis, emissions fall 31.8% against the 2017 baseline. Measured on market-based Scope 2, the 2024 figure exceeds the baseline by 13.0%. The 2017 market-based value is not disclosed, so the two bases cannot be compared like for like across time — which is precisely why this is flagged for review rather than asserted as a finding.

Four of the nine would have produced a published claim that a company failed to disclose something it had in fact disclosed. The first version of the index check reported four such findings; after the fixes, zero survived.

The lesson that transfers

The most dangerous defect in the set is the centred-label one, because the internal consistency gate passed. Equity-basis figures reconcile perfectly with each other; they are simply the wrong figures. A gate proves coherence, not correctness — the only thing that caught it was reading the source page.

§5

Limits of this pilot

  • Two company-years is not a dataset. Baseline rebasing, boundary changes and restatement frequency are time-series signals needing 5–10 years and enough companies to establish what is normal for the sector.
  • Page references cannot be verified here. Chrome re-paginates when rendering from xhtml, so no constant offset exists between claimed and actual pages — BP-1 claims page 83 and lands on PDF 31 (−52); GOV-4 claims 97 and lands on 36 (−61). Index reconciliation therefore checks whether a disclosure exists, not whether it is on the page cited. Native PDFs from investor-relations pages carry the document's own pagination and would restore the stronger check.
  • Label-to-concept mapping is hand-written — and that held up worse than expected. The earlier draft of this page guessed it "does not survive a third filer". Eight filers later it does survive, but the eighth cost the same hand work as the third: ~15 mapped labels each, in six languages. Worse, Shell's map looked correct and produced a total-assets figure 3.5× too large (107,173 against 370,350) because Docling had shifted a row label onto the wrong values. The ground-truth comparison caught it; nothing in the extractor did. In production this belongs in the taxonomy's label linkbase.
  • One extractor, eight profiles. All eight filers share a single program, but each still declares its own decimal convention, unit pattern and label map. Three failure modes only appeared once the corpus grew: a merged year header spanning a total column and a related-party sub-column (Eni — one year yielded two conflicting revenue figures, both correctly read); a print that silently clipped every value column off the right edge of the page (Galp — zero facts, the page still looked normal); and a statement split across a page break losing its heading (TotalEnergies — two tables dropped). Each is now handled fail-closed, and each was invisible at two filers.
  • Assurance level not yet captured. Whether each disclosure carries limited or reasonable assurance is a field in the schema and a signal in its own right, and is not populated for either company.
  • The label map is still the binding constraint, not the parser. Measured over the whole filing, OMV holds 349 tables / 10,605 numeric cells / 3,833 labelled rows and Aker BP 147 / 1,418 / 1,639. The extractor returns 34 and 32 facts. The cause is a hand-written map of 17 line items — running over the complete document rather than a page range yields the same 34 facts, which rules out both page selection and Docling as the limit. Enough for every accounting identity and both OMV signals; far short of the filing. The fix is the taxonomy's own label linkbase, not more hand-typed labels. The eight-filer run confirms this rather than softening it: Shell leaves 232 tagged values untouched because no label maps to them, so its 94.7% recall describes the 38 values chosen for attention, not the filing.

Next in dependency order: generate label maps from the taxonomy's label linkbase instead of by hand — the one change that removes the largest architectural weakness and is a precondition for going past eight filers without doubling the risk; extend the ESG layer to the remaining six filers, accepting the manual annotation cost; pull native PDFs to restore page-level index verification; populate assurance and boundary-change fields; and only then consider proxy labels for anything resembling a model.
